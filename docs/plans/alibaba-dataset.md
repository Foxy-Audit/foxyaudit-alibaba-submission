## 0 · The one-paragraph version

Add a `dataset/` directory to the submission repo containing labelled JSONL files
**generated by a script from corpora that already exist in the repo**, plus a
README that says, in the first sentence, that **no model was trained**. The agent
is `qwen-plus` on Alibaba Cloud Model Studio, called zero-shot with a built system
prompt and two tools. What the dataset honestly is: (a) the labelled prompt corpora
the host-side guard is measured against, (b) the exact content-blind metadata
records the judge receives for each of those prompts, (c) the judge's contract —
its system prompt and tool schemas — and (d) the schema of the human-review
feedback data the agent consults at inference time via `check_prior_reviews`.
Every label in the files is re-measured against the real SDK at generation time,
and the generator refuses to write a row whose label disagrees with the measurement.

## 1 · The fact that governs every sentence in this phase

**Nothing in this product was trained, fine-tuned, or distilled.** Verified at
`2a901c8`:

| What shapes the agent's behaviour | Where |
|---|---|
| The system prompt, built per org policy at call time | `backend/app/qwen_judge.py:332` `_build_system_prompt` |
| Two tool schemas: `flag_for_human_review`, `check_prior_reviews` | `qwen_judge.py:73` `_TOOLS`, `:127` `_PRIOR_REVIEWS_TOOL` |
| The ten-field content-blind input allowlist | `backend/app/judge.py:104` `content_blind_meta`, `:98` `SAFE_EVENT_METADATA` |
| The feedback loop: counts of prior human rulings per policy tag, last N days | `qwen_judge.py:248` `_prior_reviews_payload`, `human_reviews` table (0072) |

There is no weights file, no fine-tune job, no training run, and no corpus that
was ever fed to a model as training data. **The README must say this in its first
paragraph.** A submission about tamper-evidence that describes an evaluation
corpus as "the data we trained on" would be making exactly the kind of claim the
product exists to make detectable. The 2026-09-07 README rewrite already refused
a smaller upgrade of this kind ("The live instance runs…" before anything ran);
this is the same rule.

**What we CAN say, and it is a stronger sentence:** the agent learns from humans
*at inference time, without weight updates* — every human ruling on an escalation
is appended as a tamper-evident `human_review_resolved` event, and the agent may
read the aggregate of those rulings before it decides. The dataset ships the
schema of that data. It does not ship rows from the live box: at `2a901c8` the
deployed org holds one pending escalation and zero resolutions, and one row is
not a dataset.

## 3 · Design

> ⚠ **§3.2 and §3.4 below are the plan as written on 2026-09-07 morning and are
> superseded where they disagree with `dataset/README.md` and §8.** Specifically:
> evasions are labelled per mechanism, not uniformly uncaught; benign rows are
> measured under four tags; the signal vocabulary is `ssn_pattern`; the guard-probe
> field is `content_blind_record` plus `graded_by`, not `judge_input`; and the
> contract ships two prompts built from the OrgPolicy column defaults with the
> tools split by when the worker offers them. The generated files and the README
> are the source of truth for the shipped shape; this section is kept as the
> record of what was planned.

### 3.1 Files — all new unless marked

```
dataset/
  README.md              the honest statement, the file map, every schema, provenance, licence
  build_dataset.py       the generator; also `--check` (regenerate to memory, diff against disk)
  manifest.json          generated: sdk_version, ruleset_version, ruleset_hash, row counts per file
  guard_probes.jsonl     generated: 35 rows from sectors.py, measured
  injection_corpus.jsonl generated: 81 rows from injection_evasion_corpus.py, measured
  identifier_corpus.jsonl generated: 21 rows from identifier_corpora.py named sets, measured
  judge_contract.json    generated: system prompt (default policy config) + tool schemas + input allowlist
README.md                EDIT: one paragraph in the "Submission" section + one TOC line
```

Generated files are **committed**. A judge who clicks the link must see data, not
a script. The generator's `--check` mode is the drift guard: it is the merge gate,
and the README tells the reader how to run it.

### 3.2 Row schemas

**`guard_probes.jsonl`** — one row per `Probe`, in `SECTOR_NAMES` order then
corpus order:

```json
{
  "id": "healthcare.block.ssn",
  "sector": "healthcare",
  "policy_tag": "hipaa",
  "prompt": "Confirm coverage for member SSN 900-12-3456 before the procedure is scheduled.",
  "label": "expect_block",
  "intent": "A social security number reaching a model provider.",
  "gap_reason": "",
  "measured": {
    "triggered": true,
    "rules": ["phi.ssn"],
    "signals": ["ssn"],
    "reason": "phi"
  },
  "judge_input": {
    "prompt_hash": "<sha256 of canonical_json(prompt)>",
    "response_hash": "<sha256 of canonical_json(\"\")>",
    "token_count": 17,
    "policy_tag": "hipaa",
    "pii_signals": ["ssn"],
    "event_type": "blocked"
  }
}
```

- `label` is the corpus's own word (`expect_block` / `expect_assist` / `known_gap`).
- `measured` is `foxy_audit.check(prompt, policy_tag)` at generation time. **The
  generator asserts** `triggered == (label == "expect_block")` and exits 1 naming
  the probe otherwise — the same assertion `test_probes.py` makes. No silent drift.
- `judge_input` is the content-blind projection the judge would receive for this
  prompt, computed with the same SDK functions the wire uses (§2). `event_type` is
  `"blocked"` when `measured.triggered` else `"interaction"` — ⚠ the executor must
  read `client.py` around line 1052–1070 and `policy_engine.ENFORCEMENT_EVENT_TYPES`
  and use the **actual** event-type strings the SDK emits, not these guesses. If the
  SDK's vocabulary differs, the plan is wrong and the SDK is right.
- `response_hash` is the hash of the empty string because no response exists for an
  offline probe; the README says so. Do not invent a response.
- `pii_signals` = `sorted(set(measured.signals) | set(pii.detect_pii(prompt, "")))`,
  mirroring `client._merge_signals`. ⚠ `pii.detect_pii` is not in `foxy_audit.__all__`;
  import it as `from foxy_audit import pii` and say in the README that this is the
  same function `log_interaction` calls. The finance `known_gap` card probes are
  the reason this matters: the guard does not block them under `default`, but the
  sweep still records `credit_card` — and that is exactly what the judge sees.
- `reply` (the mock provider's fixture answer) is **excluded**. It is a canned
  string a human wrote for the testbed, not data the agent ever receives.

**`injection_corpus.jsonl`** — three kinds, all measured under `policy_tag="default"`:

```json
{"id": "evasion.spaced_letters", "kind": "evasion", "mechanism": "mechanical", "prompt": "...", "intent": "...", "why_it_passes": "...", "label": "must_not_trigger_today", "measured": {"triggered": false, "rules": []}}
{"id": "caught.injection.ignore_previous", "kind": "already_caught", "rule": "injection.ignore_previous", "prompt": "...", "label": "must_trigger", "measured": {"triggered": true, "rules": ["injection.ignore_previous"]}}
{"id": "benign.clinical.dosing", "kind": "benign", "sector": "healthcare", "near_miss": "...", "prompt": "...", "label": "must_stay_clean", "measured": {"triggered": false, "rules": []}}
```

- Assertions: `evasion` → not triggered by any `injection.*` rule (it is an evasion
  *because* it passes today; if one starts being caught, the generator must fail
  loudly and the executor reports it, not relabel it). `already_caught` → the named
  rule is in `measured.rules`. `benign` → no `injection.*` rule under `default`,
  `soc2` **and** `hipaa` (the corpus's own docstring states all three; measure all
  three, record `measured` per tag).
- ⚠ The executor must read how `sdk/tests/test_*` actually asserts each set before
  encoding the assertions, and copy those, not this table. The table is the
  intent; the test is the truth.

**`identifier_corpus.jsonl`** — only the individually asserted sets:

```json
{"id": "obligation.0", "text": "ref 0 4111111111111111", "label": "must_detect", "expected_signal": "credit_card", "measured": {"signals": ["credit_card"]}}
{"id": "placeholder.3", "text": "0000000000000000", "label": "must_not_detect", "measured": {"signals": []}}
```

Measured with `pii.detect_pii(text, "")`. ⚠ Read `test_policy_truth_1_9_0.py` for

**`judge_contract.json`**:

**`manifest.json`**: `{"sdk_version": ..., "ruleset_version": ..., "ruleset_hash": ..., "files": {"guard_probes.jsonl": 35, ...}}`.
No timestamps, no git SHA — anything that changes per commit breaks `--check`.

### 3.3 Determinism — the whole value of `--check`

- `json.dumps(row, sort_keys=True, ensure_ascii=False, separators=(",", ": "))`,
  one row per line, `\n` line endings, written with `open(..., "w", encoding="utf-8", newline="\n")`.
- `--check` regenerates every file into memory and compares **bytes** against
  disk (`open(..., "rb")`), so a CRLF checkout cannot pass by accident.
- Run the generator twice; the second run must produce zero diff.

| Excluded | Why |

The README cites the **one** measured live verdict (2026-09-07, `policy_tag=hipaa`, 51 tokens, `provider=qwen`, `model=qwen-plus`, `decision=human_review`, `risk=85`) as a single sourced example, nothing more |

## 4 · The trap that looks easy

**Calling it a training set.** Covered in §1. The README's first paragraph is the
deliverable; the JSONL is evidence for it.

**Measuring against the wrong SDK.** `import foxy_audit` on this machine resolves
to `C:\Users\Dell\Downloads\Foxy-Audit\sdk`, not the worktree. A dataset whose
`ruleset_hash` comes from a different checkout is a dataset about a different
product. Venv, `pip install -e ./sdk`, and print `foxy_audit.__file__` in the
generator's first line of output.

**Keyed vs public hashes.** In production `prompt_hash` is an HMAC under the
customer's key (`hashing.commitment_hex`), so a public dataset **cannot** carry
production-shaped hashes without a key. The keyless SHA-256 form is what
`demo/mock_llm.py` uses when no key is set, and the README must say the field is
that form and why. Do not mint a fake key to make the hashes "look real".

**CRLF.** Windows checkout, no `.gitattributes` at root. Write with
`newline="\n"`, compare bytes. Check `git diff --stat` shows no whole-file
rewrites after a second run.

**gitleaks.** The two fixture credentials will appear inside JSONL lines. They are
allowlisted by line regex, so the lines pass. Verify locally if `gitleaks` is on
the path; otherwise grep and confirm each hit is one of the two allowlisted
strings and nothing else. Do **not** add a path allowlist for `dataset/`.

**The private-key fixture.** `.gitleaks.toml` pins a fake key body
`MIIEowIBAAKCAQEAxKk9Lm2QpVrTbNc7YwH0` for a testbed fixture. `sectors.py` at
`2a901c8` does not contain it (grepped), so it should not appear in the output. If
it does, the line is allowlisted anyway; note where it came from.

**`{}` vs `None` in `_build_system_prompt`.** Both skip the policy rules block.
The README must not claim the shipped prompt is "the" prompt; it is the default
one.
